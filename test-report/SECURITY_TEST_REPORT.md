## 详细测试记录

### 1. SQL 注入攻击

**测试**:
```
POST /api/auth/staff/login
{"username": "admin' OR '1'='1", "password": "x"}
```

**结果**: 401 ❌ BLOCKED ✅

**分析**: 后端参数化查询或 ORM 防护有效，SQL 注入被正确阻止。

---

### 2. XSS 注入尝试

**测试**:
```
POST /api/auth/staff/login
{"username": "<script>alert('xss')</script>", "password": "x"}
```

**结果**: 401 ❌ BLOCKED ✅

**分析**: 不存在该用户名，返回 401。前端 `sanitize.ts` 有 XSS 清理逻辑，多一层防护。

---

### 3. 不存在的资源 ID

**测试**: `GET /api/users/00000000-0000-0000-0000-000000000000`

**结果**: 404 ✅

**分析**: 正确返回 404，未泄露敏感信息。

---

### 4. 删除不存在的资源

**测试**: `DELETE /api/users/00000000-0000-0000-0000-000000000000`

**结果**: 404 ✅

**分析**: 正确返回 404，不会误删。

---

### 5. 超大分页参数

**测试**: `GET /api/users?page=99999&pageSize=99999`

**结果**: 400 ✅

**分析**: 参数校验有效，防止资源耗尽攻击。

---

### 6. 负数分页参数

**测试**: `GET /api/users?page=-1&pageSize=10`

**结果**: 400 ✅

**分析**: 参数校验有效。

## 安全评估

### 已验证有效的安全措施

1. ✅ **JWT 认证**: 签名验证、过期检查正常
2. ✅ **参数化查询**: SQL 注入防护有效
3. ✅ **参数校验**: 边界值校验 (page, pageSize)
4. ✅ **HTTP 方法校验**: 不允许的错误方法返回 404
